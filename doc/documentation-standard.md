# 文档规范

本文档定义了在 `/doc` 目录下编写稳定、可复用、面向开发者和 coding agent 的项目文档的规范。

## 目录职责

- `/doc`：稳定、可复用、面向开发者和 coding agent 的项目文档。会被自动索引，应当可长期维护。
- `/reference`：开发过程中的临时记录、调研材料和背景资料。默认被 Git 忽略，不作为稳定入口。
- `AGENTS.md`：只放高层行为约束、入口和高频命令；不要复制主题文档的长篇细节。
- `README.md`：面向首次接触项目的简介、安装、运行和贡献入口；具体专题链接到 `/doc`。

## 单篇文档

- 一篇文档只解决一个主题；如果内容无法用一个清晰标题概括，应拆分。
- 文件名使用小写 kebab-case，例如 `ios-simulator.md`。
- 第一行使用唯一的一级标题 `# ...`；第二行空行后是摘要，描述文档的适用场景、目标和主要内容。自动化索引会读取标题和摘要，在 `doc/index.md` 生成索引。
- 开头先说明适用场景和目标，再给命令、约束、验证方式和常见故障。
- 命令必须使用仓库当前有效的路径和工具；依赖版本、环境变量和平台限制要说明原因。
- 不要把一次性的排查过程、聊天记录或未经验证的猜测写成稳定规范。

## 索引与 Git hook

- `doc/index.md` 是生成文件，不手工编辑。
- `tool/build_doc_index.sh` 扫描 `doc/*.md`，按文件名排序，读取一级标题和首段摘要生成索引。
- `.githooks/pre-commit` 在提交前重建并暂存 `doc/index.md`。首次使用仓库时执行：

  ```bash
  sh tool/install_git_hooks.sh
  ```

- 新增或重命名 `/doc` 文档后，提交前检查索引中是否出现正确标题和链接。
- 文档主题发生变化时，在同一提交中同步更新对应主题文档；不要只改索引。
